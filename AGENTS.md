## NestJS

Используй существующий стиль проекта:
```text
src/modules/<module>/
  dto/
  <module>.controller.ts
  <module>.service.ts
  <module>.module.ts
```

Контроллер — HTTP, сервис — бизнес-логика, PrismaService — БД. Не создавай второй PrismaService. DTO валидируют вход. Не помещай бизнес-логику в контроллер.

## API и безопасность

- Все приватные endpoints защищены guard.
- Права проверяются на backend.
- Пользователь магазина работает только со своим `shopId`.
- SUPER_ADMIN видит всё.
- Не возвращай `passwordHash`.
- JWT secret только в окружении.
- Для 400/404/409 используй стандартные NestJS exceptions.
- Документируй endpoints в Swagger.

Swagger ожидается на `http://localhost:3000/api`, но сначала проверь реальную конфигурацию.

## Prisma

- Один `generator`, один `datasource`.
- Никаких дублирующихся моделей.
- Обратные relation-поля обязательны.
- Для денег использовать `Decimal`, не `Float`.
- Для зависимых справочников предпочитать `isActive`, а не физическое удаление.
- Индексировать foreign keys и частые фильтры.
- До миграции проверять текущие данные и SQL.

## Главное бизнес-правило

Это внутренняя платформа, не публичный маркетплейс. Конечные клиенты пока не регистрируются, не имеют корзины и не оформляют заказ сами.

Магазины добавляют остатки. SUPER_ADMIN видит все магазины и сам продаёт детали клиентам по звонку или мессенджеру.

## Защита от дублей

Магазин не должен свободно создавать варианты вроде `колодка`, `калода`, `торм колодки`.

Архитектура:
1. Центральный справочник деталей.
2. Отдельные остатки/предложения магазинов.
3. Выбор существующей детали.
4. Новые названия проходят поиск похожих и модерацию.
5. Используются нормализация, синонимы, OEM и артикулы.
6. Нельзя решать это только `@unique name`.

## Единый поиск центрального каталога

Любой модуль, которому нужен текстовый поиск деталей, обязан использовать
`CatalogSearchService` и единый endpoint `GET /part-catalog/search`.
Запрещены отдельные Prisma/SQL-реализации поиска каталога, включая VIN-подбор,
OEM/Cross Reference, импорт прайс-листов, мобильное приложение, маркетплейс и
внешние API.
